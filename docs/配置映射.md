# Java Kafka Client 与 Sarama 配置映射

Sarama 使用 Go 结构体配置，不是 Java Kafka Client 那种字符串 key-value 配置。迁移 Java 示例时，不能直接复制 `acks=all`、`enable.auto.commit=false` 这类配置名，需要映射到 `sarama.Config` 的字段。

## 基础连接

| Java Kafka Client | Sarama | 说明 |
| --- | --- | --- |
| `bootstrap.servers` | 构造函数的 `[]string` brokers 参数 | 例如 `sarama.NewClient([]string{"localhost:9092"}, config)` |
| `client.id` | `config.ClientID` | 建议每个模块设置稳定值，便于日志、配额、审计 |
| `metadata.max.age.ms` | `config.Metadata.RefreshFrequency` | 元数据刷新周期 |
| `request.timeout.ms` | `config.Net.ReadTimeout`、`config.Net.WriteTimeout`、`config.Producer.Timeout` | 不完全一一对应，需要按场景设置 |
| `connections.max.idle.ms` | `config.Net.KeepAlive` 等网络配置 | 语义不完全等价 |

## Producer

| Java Kafka Client | Sarama | 说明 |
| --- | --- | --- |
| `acks=0` | `sarama.NoResponse` | 不等待 broker 响应，吞吐高但风险大 |
| `acks=1` | `sarama.WaitForLocal` | leader 写入即确认 |
| `acks=all` | `sarama.WaitForAll` | 等待 ISR 确认，常与 `min.insync.replicas` 配合 |
| `retries` | `config.Producer.Retry.Max` | 重试次数 |
| `retry.backoff.ms` | `config.Producer.Retry.Backoff` | Go 中使用 `time.Duration` |
| `delivery.timeout.ms` | `config.Producer.Timeout` 等组合 | 需要结合重试、网络超时理解 |
| `linger.ms` | `config.Producer.Flush.Frequency` | 批量等待时间，语义接近 |
| `batch.size` | `config.Producer.Flush.Bytes`、`Flush.Messages` | Sarama 按多种条件触发 flush |
| `buffer.memory` | 无完全对应 | 通过 channel、flush、业务队列和内存控制实现 |
| `compression.type` | `config.Producer.Compression` | gzip、snappy、lz4、zstd 等视版本和 broker 支持 |
| `enable.idempotence` | `config.Producer.Idempotent` | 需同时满足 broker 版本、acks、in-flight 等要求 |
| `transactional.id` | `config.Producer.Transaction.ID` | 用于事务 producer |
| `max.in.flight.requests.per.connection` | `config.Net.MaxOpenRequests` | 幂等和顺序场景要谨慎 |
| `key.serializer` | 应用代码或 `sarama.Encoder` | Sarama 不通过配置指定 serializer class |
| `value.serializer` | 应用代码或 `sarama.Encoder` | JSON/Protobuf/Avro 通常在业务层编码 |
| `partitioner.class` | `config.Producer.Partitioner` | 可选择或自定义分区器 |

## Consumer

| Java Kafka Client | Sarama | 说明 |
| --- | --- | --- |
| `group.id` | `sarama.NewConsumerGroup` 的 groupID 参数 | 不在 `Config` 中单独设置 |
| `enable.auto.commit` | `config.Consumer.Offsets.AutoCommit.Enable` | 手动提交时设为 `false` 或谨慎使用 |
| `auto.commit.interval.ms` | `config.Consumer.Offsets.AutoCommit.Interval` | 自动提交间隔 |
| `auto.offset.reset` | `config.Consumer.Offsets.Initial` | `sarama.OffsetOldest` 或 `sarama.OffsetNewest` |
| `isolation.level` | `config.Consumer.IsolationLevel` | `ReadUncommitted` 或 `ReadCommitted` |
| `max.poll.records` | 无直接等价 | Sarama 是 handler + channel 模型，可通过批处理和业务限流控制 |
| `max.poll.interval.ms` | 无完全等价 | 关注 handler 阻塞、rebalance timeout、session timeout |
| `session.timeout.ms` | `config.Consumer.Group.Session.Timeout` | 影响故障检测和 rebalance |
| `heartbeat.interval.ms` | `config.Consumer.Group.Heartbeat.Interval` | 应明显小于 session timeout |
| `partition.assignment.strategy` | `config.Consumer.Group.Rebalance.GroupStrategies` | range、roundrobin、sticky 视 Sarama 版本支持 |
| `group.instance.id` | `config.Consumer.Group.InstanceId` | 静态成员，适合稳定实例身份 |
| `fetch.min.bytes` | `config.Consumer.Fetch.Min` | broker 返回前等待的最小数据量 |
| `fetch.max.bytes` | `config.Consumer.Fetch.Max` | 拉取大小上限 |
| `fetch.max.wait.ms` | `config.Consumer.MaxWaitTime` | broker 等待更多数据的时间 |

## 安全

| Java Kafka Client | Sarama | 说明 |
| --- | --- | --- |
| `security.protocol=SASL_PLAINTEXT` | `config.Net.SASL.Enable=true` | 不启用 TLS |
| `security.protocol=SASL_SSL` | `config.Net.SASL.Enable=true` + `config.Net.TLS.Enable=true` | SASL + TLS |
| `sasl.mechanism` | `config.Net.SASL.Mechanism` | PLAIN、SCRAM、OAUTHBEARER 等视版本支持 |
| `sasl.username` | `config.Net.SASL.User` | 用户名 |
| `sasl.password` | `config.Net.SASL.Password` | 密码 |
| `ssl.truststore.location` | `tls.Config.RootCAs` | Go 通常加载 PEM CA，不直接使用 Java truststore |
| `ssl.keystore.location` | `tls.Config.Certificates` | Go 使用 client certificate |
| `ssl.endpoint.identification.algorithm` | `tls.Config.ServerName` / `InsecureSkipVerify` | 不建议在生产跳过校验 |

## 迁移注意事项

- Sarama 的序列化通常由应用代码负责，Java 的 serializer 配置不能照搬。
- Sarama consumer group 不是显式 `poll()` 循环，很多 Java poll 相关配置没有一一对应字段。
- 幂等 producer 不是只开一个布尔值，还要检查 `RequiredAcks`、`Net.MaxOpenRequests`、broker 版本和错误处理。
- 事务语义只解决 Kafka 链路内的一部分一致性问题，写外部 DB 仍要做业务幂等或事务协调。
- 配置字段会随 Sarama 版本演进，实际代码应以项目锁定版本的文档和 IDE 类型提示为准。
